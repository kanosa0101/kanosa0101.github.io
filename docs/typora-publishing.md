# Typora 写作与一键发布

日常只需要：**在 Typora 保存 → 双击 `发布文章.cmd` → 选择原稿 → 检查通过后点击发布**。

也可以把 `.md` 文件拖到 `发布文章.cmd` 上。工具只负责发布，不替代 Typora 编辑器，也没有后台常驻服务。

## 原稿与图片

- 原稿可以放在自己的笔记文件夹。博客文件夹以外的原稿不会被改动；工具生成发布副本。
- Typora 使用默认图片文件夹或 `文章.assets/` 都可以，原图片文件要保留在本机。
- 相对路径、Windows 绝对路径、`file://`、中文和空格路径、Markdown 引用式图片及 `<img src="…">` 都会检查并转换。`typora-root-url` 也会参与定位。
- 本地图片复制到 `source/images/posts/`，使用内容指纹命名，避免同名覆盖并自动去重。文章的封面等图片字段同样处理，HTML 图片尺寸属性保留。
- 找不到图片或文件并非支持的图片格式时会停止发布。正文代码块中的图片示例保持原样。
- 外链图片保留原链接，能否显示仍取决于原站。带有本地外部依赖的 SVG 和 HTML `srcset` 会提示先处理，避免上传后出现破图。
- 如果直接选择 `source/_posts/` 中的文章，工具会规范化其链接，并在 `.blog-publish/originals/` 留一份原文备份；推荐日常原稿放在博客目录外。

## 文章信息

可以在 Typora 原稿开头填写以下信息；不填写时，工具从一级标题或文件名获取标题，生成发布日期，分类默认为“经验分享”。发布窗口可以选择论文介绍、经验分享或课程笔记。

```yaml
---
title: 我的论文阅读笔记
date: 2026-10-14 20:00:00
categories:
  - 论文介绍
tags:
  - 大语言模型
description: 这篇文章介绍了什么。
---
```

文件名决定文章链接的一部分，请让不同文章使用不同文件名；同名文章会作为更新，窗口会明确提示并再次确认。更新时原稿没有填写日期，就沿用博客中的发布日期，避免链接漂移。

## 发布过程

工具在独立目录构建，检查生成网页中的相对和绝对资源链接、本地图片、页面模板；通过后才将文章和图片保存到博客，提交并推送 `source`，随后推送生成页面到 `main`。不强制推送，也不会顺带提交其他站点修改。

“成功推送”后，GitHub Pages 还需要片刻部署，点击“查看线上博客”即可访问。网络错误可重新检查后重试，已经上传的内容不需要重写。

首次换电脑时需要安装 Node.js 22+、Git，并在项目目录执行一次 `npm ci`，配置好自己的 GitHub 登录。现有电脑已经具备这些条件。

本机代理可配置在被 Git 忽略的 `.blog-publish/settings.json`，例如：

```json
{"proxy":"socks5h://127.0.0.1:10808"}
```

代理只用于本工具的 Git 命令，不改变系统或全局 Git 设置。`.blog-publish/` 中是本机日志、构建缓存和备份，不会上传。

开发验证：`npm run test:publish`。集成测试使用独立的本地 Git 远端，不向 GitHub 发布测试文章。
